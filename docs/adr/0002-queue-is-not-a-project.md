# The queue is not a project, and its workers never wait on the engineer

afk's queue works through standalone, low-priority tickets unattended, one at a time, each ending in a draft PR. We built it as its own standing, machine-wide thing beside projects, reusing their worker machinery (worktrees, slots, hooks, phases, watcher), rather than as an always-open project: a project's spec, frontier, Gate 1, landing mode and close-when-done would each need bending for it. Its workers never stop to ask: a question or blocker becomes a best-effort assumption and a line under `## Questions for the engineer` in the draft PR, and a runaway worker is told to wrap up and is then abandoned, so one ticket can never stall the queue. The engineer re-enqueues a ticket once they've answered it. For the same reason a draft gets local critique instead of bot review, since bots like Copilot skip drafts and the queue spends no attention on triaging them.
