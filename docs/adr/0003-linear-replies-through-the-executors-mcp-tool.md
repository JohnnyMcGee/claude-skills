# Linear replies go through the executor's Linear MCP tool, not a pinned step

An approved `linear_reply` is posted by the executor with `mcp__linear-server__save_comment`, not by a `process execute` step that sends the approved text itself, the way GitHub reviews and replies are. A pinned step would need a Linear API key, and `process` holds no Linear credential: Linear is reached only through the remote OAuth MCP server. We accepted a weaker guarantee to avoid adding one: the executor relays the draft, so nothing in code checks that the posted comment is the approved text, or that it creates a comment rather than editing one. execute/SKILL.md tells it to post the draft byte for byte and never pass a comment id. This is the same trust the executor already gets for `linear_promote` through `save_issue`. Triage and the sweepers still may not hold the tool (`forbidden_tool`), so only an approved entry can reach it. If Linear replies ever need the exact-text guarantee, add a `process execute linear-reply` step with its own key and drop the MCP tool from the executor.
