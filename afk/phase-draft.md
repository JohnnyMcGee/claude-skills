AFK phase: draft — ticket {{ticket}} ({{ticket_path}})

The branch is critiqued. Open it as a draft PR, for the engineer to review whenever they get to it. Nobody is waiting on you, and nobody will answer a question here.

1. Push the branch: `git push -u origin HEAD`. Never force-push, and never push to `{{base}}`.
2. Write the PR description with a shell heredoc to a file in your worktree's git directory, untracked and yours alone: `cat > "$(git rev-parse --git-dir)/afk-pr-body.md" <<'EOF'`. Use the shell, here and whenever you change it, as your Edit and Write tools work only on the worktree's files. It says what was done and why, and links the ticket ({{ticket_path}}). It ends with a `## Questions for the engineer` section listing every question, assumption and blocker you ran into in any phase, each with the assumption you made and what's still needed; write `None.` under it if there were none. That section is always the last.
3. Open a draft PR against `{{base}}`: `gh pr create --draft --base {{base}} --title "<conventional commit title>" --body-file "$(git rev-parse --git-dir)/afk-pr-body.md"`. If GitHub refuses a draft because draft PRs aren't available for this repo, open a normal PR labelled `Draft` instead: `gh label create Draft --description "Not ready for review"` (an "already exists" error is fine), then the same `gh pr create` with `--label Draft` in place of `--draft`. Never run `gh pr ready`, never request a reviewer and never merge.
4. Wait for CI: `gh pr checks --watch`. If a check fails, fix it, commit, push and wait again, for at most {{ci_rounds}} rounds of fixes. Don't triage bot review comments: bots skip drafts, and the engineer reads the PR. If checks still fail after {{ci_rounds}} rounds, add each failing check, with what you know of why it fails, to `## Questions for the engineer`, rewriting the file with the shell, and update the PR: `gh pr edit --body-file "$(git rev-parse --git-dir)/afk-pr-body.md"`.

When the draft is open and CI has passed or its failures are listed, run `afk report done "<one-line summary>"`. afk finds the PR by your branch, so you don't need to report its URL.
